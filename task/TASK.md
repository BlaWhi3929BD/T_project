# Задание: дашборд аналитики по сделкам

Срок: **5 рабочих дней.** Стек: **FastAPI (Python 3.11+) + React 18 + TypeScript + Vite.**

## Что должно получиться

Одностраничный дашборд: фильтры → метрики → график накопленного результата →
таблица сделок. Плюс API, который его питает.

## Данные

```
python3 data/seed.py    # создаст data/trades.csv, 100 000 строк
```

Генерация детерминирована: у меня и у тебя файл будет одинаковым. `seed.py` и
`trades.csv` — входные данные, **править их нельзя.**

Колонки: `id, symbol, strategy, side, opened_at, closed_at, qty, entry_price,
exit_price, fee, pnl`. Все временные метки — UTC, ISO 8601 с `Z`. `pnl` — итог
сделки в USDT с точностью до копейки, уже с учётом комиссии; знак — результат.

Загрузка CSV в БД — твоя часть работы. БД на твой выбор (SQLite или Postgres),
выбор обоснуй.

## Терминология

- **Календарные сутки** здесь — сутки в таймзоне **`Asia/Almaty`**. Все дневные
  группировки и все фильтры по датам работают в ней. Сделка относится к суткам по
  своему `closed_at`.
- **Выигрышная сделка** — `pnl > 0`. **Убыточная** — `pnl < 0`. Сделки с `pnl == 0`
  в датасете есть; куда их относить — решаешь ты и записываешь решение.
- **max drawdown** — максимальная просадка кривой накопленного `pnl`, построенной
  по календарным суткам: наибольшая величина «локальный максимум минус текущее
  значение». Всегда `>= 0`.

## Часть 1. API

Все денежные значения в JSON передавай **строками** (`"1234.56"`), не числами.
Коэффициенты (`win_rate`, `profit_factor`) — числами или `null`.

Фильтры одинаковые у всех эндпоинтов и все опциональные:

| Параметр | Формат | Смысл |
|---|---|---|
| `symbol` | повторяемый (`?symbol=BTCUSDT&symbol=ETHUSDT`) | любой из перечисленных |
| `strategy` | повторяемый | любая из перечисленных |
| `side` | `long` \| `short` | — |
| `date_from` | `YYYY-MM-DD` | календарные сутки, **включительно** |
| `date_to` | `YYYY-MM-DD` | календарные сутки, **включительно** |

### `GET /api/filters/options`

```json
{ "symbols": ["ADAUSDT", "..."], "strategies": ["breakout_v1", "..."] }
```

Список берётся из данных, не из хардкода.

### `GET /api/trades`

Дополнительно: `sort` (`closed_at` | `pnl` | `symbol`, по умолчанию `closed_at`),
`order` (`asc` | `desc`, по умолчанию `desc`), `page` (с 1), `page_size`
(по умолчанию 50, максимум 200).

```json
{
  "items": [
    {
      "id": 42, "symbol": "BTCUSDT", "strategy": "momentum_v1", "side": "long",
      "opened_at": "2024-03-10T15:41:00Z", "closed_at": "2024-03-10T18:59:59Z",
      "qty": "0.012", "entry_price": "61980.00", "exit_price": "62410.00",
      "fee": "0.74", "pnl": "4.42"
    }
  ],
  "page": 1, "page_size": 50, "total": 12345
}
```

`total` — количество сделок во всей отфильтрованной выборке, не на странице.

### `GET /api/stats`

Пагинации нет: метрики считаются по всей отфильтрованной выборке.

```json
{
  "trades_count": 12345,
  "wins": 5600, "losses": 6500, "breakeven": 245,
  "net_pnl": "1234.56",
  "gross_profit": "9876.54",
  "gross_loss": "8641.98",
  "win_rate": 0.4536,
  "profit_factor": 1.1429,
  "avg_win": "1.76", "avg_loss": "-1.33",
  "best_trade": "84.20", "worst_trade": "-61.05",
  "max_drawdown": "312.40",
  "equity_curve": [
    { "date": "2024-01-01", "day_pnl": "12.40", "cum_pnl": "12.40" }
  ]
}
```

Правила, которые обязаны выполняться:

- `gross_loss` — положительная величина (модуль убытков).
- `win_rate` = `wins / trades_count`; `null`, если сделок нет.
- `profit_factor` = `gross_profit / gross_loss`; `null`, если `gross_loss` равен нулю.
- `avg_win` — `null`, если выигрышных сделок нет; `avg_loss` — аналогично.
- `max_drawdown` — `"0.00"`, если просадки не было.
- `equity_curve` — **непрерывный** ряд календарных суток от первых до последних
  сделок выборки. Сутки без сделок присутствуют с `day_pnl: "0.00"` и неизменным
  `cum_pnl`. Пропускать их нельзя.
- Пустая выборка не должна приводить к ошибке 500.

### Контрольные значения

Значения для самопроверки. На **полном датасете без фильтров** должно
получиться ровно:

```
trades_count : 100000
net_pnl      : "20373.96"
```

`net_pnl` — именно `"20373.96"`, а не `"20373.96000000001"` и не `"20373.95"`.
Если получается другое число — где-то теряются или искажаются деньги.
Остальные метрики сверяются при приёмке.

## Часть 2. Фронтенд

Одна страница, сверху вниз:

1. **Панель фильтров:** symbol (мультивыбор), strategy (мультивыбор), side,
   диапазон дат.
2. **Строка метрик:** net PnL, win rate, profit factor, max drawdown, количество
   сделок. Прибыль и убыток различимы визуально.
3. **График** накопленного `cum_pnl` по суткам.
4. **Таблица сделок** с пагинацией и сортировкой по клику на заголовок.

Библиотека графиков — любая. Дизайн-система не нужна, но верстка не должна
разъезжаться и на 1280px, и на 1920px.

## Требования к поведению

Это не пожелания, это часть приёмки.

1. **Точность денег.** Сумма значений `pnl` из `/api/trades` по всем страницам
   выборки обязана совпадать с `net_pnl` из `/api/stats` до копейки. Ровно, без
   «погрешности в последнем знаке».
2. **Сутки.** Фильтр `date_from`/`date_to` и группировка в `equity_curve` работают
   в `Asia/Almaty`. Сделка, закрытая в 18:59:59Z, и сделка, закрытая в 19:00:00Z,
   относятся к разным календарным суткам.
3. **Метрики против пагинации.** Смена `page` не меняет ни одного значения в
   `/api/stats`.
4. **Скорость.** На полном датасете без фильтров: `/api/stats` — p95 меньше 200 мс,
   `/api/trades` — p95 меньше 100 мс. Замер локально, 10 прогонов после прогрева,
   способ замера приложи в README.
5. **Детерминированность пагинации.** Постраничный обход выборки возвращает каждую
   сделку ровно один раз: без дублей и без пропусков. В данных есть сделки с
   абсолютно одинаковым `closed_at` — это нормальная ситуация, не баг данных.
6. **Ссылка на состояние.** Фильтры, сортировка и номер страницы живут в URL.
   Ссылку можно переслать коллеге и он увидит тот же дашборд. F5 ничего не сбрасывает.
7. **Актуальность отображаемого.** Если быстро переключать фильтры, на экране
   всегда данные, соответствующие текущим фильтрам, а не тем, что были три клика назад.
8. **Состояния интерфейса.** Загрузка, ошибка запроса, пустая выборка — все три
   выглядят осмысленно. Нигде в UI не появляются `NaN`, `Infinity`, `undefined`,
   `null` и пустые ячейки без объяснения.

## Тесты

Минимум 10 автотестов на бэкенде. **Список проверяемых краевых случаев
составляешь сам** и выписываешь в `DECISIONS.md` с объяснением, почему именно эти.

Фронтовые тесты по желанию, но пункты 6 и 7 нужно чем-то показать — тестом или
записью экрана.

## Что НЕ надо делать

Всё перечисленное вне рамок задания:

- авторизацию, роли, регистрацию;
- деплой, CI, Kubernetes, больше одного контейнера;
- WebSocket и real-time обновления;
- вторую страницу, роутинг между экранами, тёмную тему;
- микросервисы, event sourcing, кэш-слой на Redis;
- «а ещё я добавил» — любую функциональность, которой нет выше.

Если считаешь что-то из списка необходимым — обоснуй в `DECISIONS.md` и не делай.

решениях. Формат каждой:

```
## Решение: краткое название
Контекст:      что нужно было решить
Варианты:      какие были рассмотрены
Выбрал:        что в итоге в коде

```

Записи нужны по всем неочевидным местам: выбор БД, где считаются агрегаты, что
считать выигрышной сделкой, как обеспечена детерминированность пагинации, как
хранится состояние дашборда.
